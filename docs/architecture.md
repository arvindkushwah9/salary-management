1. Rails API backend
2. Next.js frontend

## 2. Backend

The backend uses:

* Ruby 3.3.3
* Rails 8.1.3.1
* PostgreSQL
* UUID primary keys
* JWT authentication
* bcrypt password hashing
* RSpec
* Rswag/OpenAPI
* Pagy

The Rails application exposes versioned API endpoints under:

```text
/api/v1
```

## 3. Frontend

The frontend uses:

* Next.js 16.3.5
* React 19.2.8
* TypeScript
* Tailwind CSS v4
* React Hook Form
* Zod
* Recharts
* Lucide React

The frontend communicates with the Rails API through a centralized API client.

## 4. Authentication

The login endpoint is public.

Successful authentication returns a JWT.

Subsequent requests include:

```http
Authorization: Bearer <TOKEN>
```

The Rails API authenticates the token and establishes the current user for the request.

## 5. Domain Model

The main relationships are:

```text
Department
    │
    └── has_many Employees
                 │
                 ├── has_many SalaryStructures
                 │
                 └── has_many Payslips
                              │
                              └── has_many PayslipItems

PayrollRun
    │
    └── has_many Payslips
```

A payroll run therefore acts as the parent of the generated payslips, while each payslip contains the employee-specific payroll result.

## 6. Salary History

Salary structures are effective-dated.

The current salary is selected using:

```text
effective_from <= target date
AND
effective_to IS NULL OR effective_to >= target date
```

The most recent matching structure is selected.

This allows historical salary changes without overwriting previous records.

## 7. Payroll Processing

Payroll processing is isolated in:

```text
Payroll::ProcessService
```

The service:

1. Validates payroll state.
2. Starts a database transaction.
3. Sets the payroll run to processing.
4. Iterates through active employees.
5. Finds the current salary.
6. Skips employees without an applicable salary.
7. Skips salary structures with a different currency.
8. Creates payslips.
9. Creates earning items.
10. Recalculates payroll totals.
11. Marks the payroll run approved.

The transaction protects against partially processed payroll runs.

## 8. Payslip Totals

Payslip totals are recalculated from persisted payslip items.

Deductions are calculated from:

```text
deduction + statutory
```

Net pay is:

```text
gross earnings - total deductions
```

Payroll totals are subsequently recalculated from all payslips in the payroll run.

## 9. Currency Boundary

Payroll runs contain a currency.

A salary structure is included only when its currency matches the payroll run currency.

The implementation intentionally does not perform currency conversion.

This prevents different currencies from being aggregated into one payroll total without an explicit conversion policy.

## 10. API Documentation

Rswag generates OpenAPI documentation for the API.

The application exposes Swagger UI under:

```text
/api-docs
```

The generated specification is available through the configured OpenAPI endpoint.

## 11. Frontend Data Flow

```text
Page / Component
       │
       ▼
src/lib/api.ts
       │
       ▼
Rails API
       │
       ▼
JSON response
       │
       ▼
TypeScript model
       │
       ▼
UI state
```

The centralized API client is responsible for:

* API base URL
* Authentication headers
* JSON requests
* API error extraction
* File downloads

## 12. Exports

Exports are generated by the backend.

Supported formats:

```text
Payroll → CSV
Payroll → Excel
Payslip → PDF
```

The frontend downloads the generated files through authenticated requests.

## 13. Error Handling

The API returns structured errors such as:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "..."
  }
}
```

The frontend translates API failures into visible error states and toast notifications where appropriate.

## 14. Transaction Boundaries

Two important workflows are transactional:

### Payroll Processing

Payroll run creation of payslips and totals is transactional.

### Payslip Item Changes

Adding or removing a payslip item recalculates:

```text
Payslip totals
       ↓
Payroll totals
```

within a transaction.

## 15. Future Architecture Extensions

For a production payroll platform with significantly larger workloads, the architecture could evolve to include:

* Background payroll jobs
* Job queues
* Payroll processing progress
* Audit logging
* Stronger role-based access control
* MFA
* Country-specific tax modules
* Attendance/leave integrations
* Banking/payment integrations
* Dedicated payroll calculation workers
* Caching for dashboard aggregates

These were intentionally not introduced without corresponding requirements.
